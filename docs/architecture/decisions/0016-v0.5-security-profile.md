# ADR 0016: v0.5 endpoint and callback security profile

- Status: Superseded in part by ADR 0021
- Date: 2026-08-26

## Context

The public preview crosses authenticated inbound HTTP and subscriber-controlled
outbound HTTP boundaries. Slice 6 cannot proceed until the preview establishes
which endpoint authentication, callback SSRF, and secret-protection controls
are mandatory rather than deferred deployment guidance.

## Decision

ADR 0021 supersedes the mandatory inbound JWT requirement below with explicit
per-listener `none` or `jwt` modes. The JWT profile remains authoritative when
a listener selects `jwt`; all callback and secret-protection decisions remain
authoritative in every mode.

All public protocol and protected administration requests require a signed JWT.
WebSubHub validates signatures against a configured HTTPS JWKS endpoint and
fails closed. Configuration pins the exact issuer, audience, and permitted
asymmetric signature algorithms, applies bounded clock skew and JWKS caching,
and limits bearer-token size. The `none` algorithm and symmetric algorithms are
not supported. An unavailable issuer never downgrades authentication.

Authorization maps each protocol operation to a required product scope:

```text
websubhub:topic:register
websubhub:topic:deregister
websubhub:content:publish
websubhub:subscription:create
websubhub:subscription:delete
websubhub:ops:read
websubhub:ops:write
```

Health liveness remains unauthenticated for orchestrators. Readiness exposes
only a bounded status and reasons without state or dependency credentials.
Capabilities and inspection require `websubhub:ops:read`; mutations require
`websubhub:ops:write`. Authentication does not replace callback intent
verification or future per-topic policy.

Callback URLs are checked at admission and again for every connection. The
secure default permits HTTPS only, refuses userinfo, fragments, redirects, and
environment proxies, constrains ports, and rejects loopback, private,
link-local, multicast, carrier-grade NAT, documentation, benchmark, reserved,
unspecified, and cloud-metadata destinations for IPv4 and IPv6. Explicit host
and CIDR allowlists may permit trusted private or HTTP callbacks for development
and enterprise deployments; they never become global insecure modes.

Subscription HMAC secrets use AES-256-GCM with a 32-byte key loaded from a
secret file and a configured key identifier. Plaintext is never persisted.
State retains ciphertext and key ID so a later multi-key rotation provider can
be introduced without changing the state shape.

Hub-to-consolidator authentication remains the independent `mtls` or `none`
decision in ADR 0009. mTLS is recommended; `none` is limited to an isolated
trusted network.

## Consequences

- A v0.5 listener configured in `jwt` mode requires an identity provider with
  JWKS.
- JWT issuer outage or an expired JWKS cache rejects new protected requests;
  it does not affect already admitted asynchronous delivery.
- OIDC discovery is not implicit: operators configure the exact issuer and
  JWKS URL, avoiding discovery-time trust expansion.
- Fine-grained topic policy, KMS-backed envelope encryption, key rotation, and
  operator-write actions remain future work and must be reported honestly.
  Unauthenticated listener behavior is governed by ADR 0021.
